GIẢI PHÁP HỆ THỐNG THU THẬP VÀ PHÂN TÍCH HÀNH VI ĐỌC TIN TỨC (PHẦN I)

CÂU 1: THU THẬP DỮ LIỆU TRÌNH DUYỆT
- Kỹ thuật thu thập: Sử dụng Content Script của Chrome Extension để parse DOM (trích xuất URL, Domain, Title, Content) trên 3 trang web mục tiêu [cite: 2].
- Cách tính thời gian đọc thực tế: Thay vì tính thời gian mở tab, áp dụng Page Visibility API để bắt trạng thái 'visible/hidden'. Kết hợp lắng nghe các sự kiện (scroll, mousemove, keydown) để đảm bảo người dùng đang tương tác. Nếu không có tương tác sau 30 giây, chuyển trạng thái sang "Idle".

CÂU 2: THIẾT KẾ EVENT
- Cấu trúc dữ liệu:
  {
    "event_id": "uuid-...",
    "session_id": "session-uuid",
    "event_type": "PAGE_ENTER", // Hoặc PAGE_ACTIVE, PAGE_INACTIVE, PAGE_LEAVE [cite: 2]
    "url": "https://...",
    "title": "...",
    "content": "...", // Chỉ đính kèm ở PAGE_ENTER
    "timestamp": 1690000000
  }
- Quản lý session_id: Tạo một UUID duy nhất (crypto.randomUUID) mỗi khi tab mới tải trang (PAGE_ENTER). Lưu vào biến bộ nhớ của Content Script để đính kèm vào các event tiếp theo của tab đó.
- Lý do lưu dạng Event: Lưu event giúp vẽ được timeline chi tiết về hành vi đọc [cite: 2], tính toán thời gian chính xác kể cả khi người dùng chuyển tab liên tục, và không bị mất toàn bộ dữ liệu nếu trình duyệt đóng đột ngột (không kịp gửi bản ghi tổng hợp).

CÂU 3: CENTRAL SERVER
- Tech stack đề xuất: NestJS kết hợp MySQL (tương tự dự án đặt lịch khám bệnh) để xây dựng API nhanh chóng và dễ mở rộng.
- API endpoints:
  + POST /api/events: Nhận và validate payload (sử dụng class-validator), lưu vào bảng `events` [cite: 2].
  + GET /api/sessions: Truy vấn danh sách các phiên đọc bằng cách group by `session_id` [cite: 2].
  + GET /api/articles: Truy vấn và trả về danh sách các bài báo đã được đọc [cite: 2].

CÂU 4: DASHBOARD
- Tech stack đề xuất: ReactJS kết hợp TailwindCSS.
- Thiết kế:
  + Trang chủ hiển thị danh sách bài báo đã đọc với timeline event tương ứng [cite: 2]. Thiết lập Socket.io để cập nhật realtime khi có sự kiện mới.
  + Tích hợp thư viện Chart.js hoặc Recharts để vẽ biểu đồ thống kê tổng thời gian đọc theo domain và theo ngày [cite: 2].

CÂU 5: XỬ LÝ TÌNH HUỐNG THỰC TẾ
1. Mở nhiều tab: `session_id` được sinh riêng biệt theo từng tab nên dữ liệu không bị xung đột [cite: 2].
2. Chuyển tab liên tục: Page Visibility API sẽ trigger liên tục `PAGE_INACTIVE` và `PAGE_ACTIVE` tương ứng [cite: 2]. Central Server sẽ tính tổng khoảng thời gian giữa các cặp Active - Inactive.
3. Không thao tác (Idle): Set timeout (VD: 30s). Nếu không có sự kiện scroll/mouse, trigger event `PAGE_INACTIVE` [cite: 2].
4. Đóng Chrome đột ngột: Sử dụng Background Script (`chrome.tabs.onRemoved`) để gửi `PAGE_LEAVE`. Kết hợp cơ chế ping định kỳ (heartbeat) từ Content Script.
5. Gửi event nhiều lần: Thêm trường `event_id` (UUID). Server dùng `event_id` làm khóa duy nhất (Idempotency key) để bỏ qua bản ghi trùng lặp [cite: 2].
6. Mất kết nối Internet: Content Script lưu tạm các event vào `chrome.storage.local`. Khi có mạng trở lại (lắng nghe sự kiện `online`), Background Script sẽ đồng bộ lên Server [cite: 2].
7. Website đổi cấu trúc HTML: Sử dụng các thẻ meta (og:title, og:description) hoặc các selector chuẩn (như thẻ <article>, <h1>) thay vì phụ thuộc vào các class CSS cụ thể [cite: 2]. Có thể thiết kế cơ chế cấu hình selector tải động từ server.
